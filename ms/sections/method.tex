\section{A server-side selection step, and exact comparators}
\label{sec:method}

Proposition~\ref{prop:orth}(iv) identifies a specific defect---the
aggregation step returns a dense vector---and suggests an equally specific
remedy: apply the proximal operator of the $\ell_1$ penalty at the server,
where the aggregation happens.

\subsection{\textsc{FedAvg-ST}: thresholding after convergence}

Let $\bbeta_R$ be the output of Algorithm~\ref{alg:fedavg} after $R$ rounds.
\textsc{FedAvg-ST} adds a single round in which the server broadcasts a grid
$\mathcal{T}$ of candidate thresholds and each site returns, for each
candidate $\tau$, the three scalars
\begin{equation}
A_j(\tau) = \sum_{i=1}^{m_j^{\mathrm{val}}} r_{ji}(\tau)^2, \qquad
B_j(\tau) = \sum_{i=1}^{m_j^{\mathrm{val}}} r_{ji}(\tau)^4, \qquad
m_j^{\mathrm{val}} ,
\label{eq:scalars}
\end{equation}
where $r_{ji}(\tau) = y_{ji} - x_{ji}^\top \soft(\bbeta_R, \tau)$. These are
sufficient for both the weighted validation mean squared error
$\widehat{\mathrm{MSE}}(\tau) = \sum_j w_j A_j(\tau)/m_j^{\mathrm{val}}$ and
the observation-level standard error of the squared residuals,
$\widehat{\mathrm{SE}}(\tau)^2
 = \{\sum_j B_j(\tau) - (\sum_j A_j(\tau))^2/n_{\mathrm{val}}\}
   /\{n_{\mathrm{val}}(n_{\mathrm{val}}-1)\}$ with
$n_{\mathrm{val}} = \sum_j m_j^{\mathrm{val}}$; no second pass and no
row-level exchange is required. The server then selects
\begin{equation}
\hat\tau = \max\Big\{\tau \in \mathcal{T} :
  \widehat{\mathrm{MSE}}(\tau) \le
  \widehat{\mathrm{MSE}}(\tau_{\min}) + \widehat{\mathrm{SE}}(\tau_{\min})\Big\},
\qquad
\hat\bbeta^{\mathrm{ST}} = \soft(\bbeta_R, \hat\tau),
\label{eq:st}
\end{equation}
where $\tau_{\min}$ minimises $\widehat{\mathrm{MSE}}$ over the grid. This is
the familiar one-standard-error rule applied to a threshold rather than to a
penalty. The minimum-MSE rule is not used because it selects
$\hat\tau \approx 0$ and returns the dense iterate unchanged; we report that
variant (\textsc{FedAvg-ST-min}) so the reader can see the effect of the rule
rather than take it on trust. Because the one-standard-error rule favours
sparsity, every baseline in Section~\ref{sec:sim} is reported under both
rules (Section~\ref{sub:matched}).

The extra round transmits $3|\mathcal{T}|$ scalars per site rather than a
$p$-vector. With $|\mathcal{T}| = 40$ and $K = 3$ this is $2.8$~KiB, against
$14.1$~KiB for one round of coefficient vectors, and we account for the two
separately in all cost tables.

\subsection{\textsc{FedAvg-P}: proximal aggregation}

\textsc{FedAvg-ST} repairs the output; it does not repair the iteration.
The natural composite fix is to apply the proximal operator at the server in
\emph{every} round, $\bbeta_{t+1} \gets \soft(\sum_j w_j \bbeta_{j,t}, \tau)$,
which is the coordinate-descent analogue of the server-side correction that
motivates FedDualAvg \citep{yuan2021fco} and the federated dual-averaging
methods of \citet{bao2022}. The threshold matters: fixing $\tau = \bar\lambda$
compounds shrinkage across rounds and over-sparsifies badly, so we select
$\tau$ over a five-point grid $\bar\lambda \cdot \{1, \tfrac12, \tfrac14,
\tfrac18, \tfrac1{16}\}$ by the same one-standard-error rule on the same
scalar summaries. We do not implement FedDualAvg itself: it replaces exact
local coordinate descent with local dual-averaging steps, which changes what
$E$ means and would make the local-epoch comparison incoherent. A comparison
at fixed communication budget between the two families is worth doing and we
do not attempt it here.

\subsection{Comparators}

We compare against four alternatives, all fitted on identical data.

\paragraph{Pooled Lasso.} The centralised fit on the concatenated sample,
with its penalty tuned by validation MSE on the concatenated validation
split. This is the infeasible reference an analyst would use if the data
could be centralised. Note that it is tuned independently and therefore
generally uses a penalty different from $\bar\lambda$.

\paragraph{Consensus ADMM.} The alternating direction method of multipliers
in global consensus form \citep{boyd2011} applied to $F$: each site solves a
ridge-regularised least-squares subproblem by a Cholesky factorisation
computed once, the server soft-thresholds the averaged primal-plus-dual
variable, and duals are updated locally. By Lemma~\ref{lem:pooled} this
returns the pooled Lasso solution at $\bar\lambda$ to numerical precision,
using the same communication pattern (one $p$-vector per site per iteration)
and the same privacy boundary as Algorithm~\ref{alg:fedavg}. It is therefore
the right control: it isolates the effect of \emph{how} the sites are
combined, holding the objective, the data and the communication channel
fixed. Because ADMM inherits its penalty from the local $\lambda_j$, we also
report \textsc{ADMM-CV}, in which the consensus penalty is selected over a
$15$-point grid by federated validation, under both selection rules. This
separates ``exact optimisation'' from ``a fortunate value of
$\bar\lambda$''---a distinction that turns out to matter
(Section~\ref{sec:results}).

\paragraph{One-shot averaging.} Each site solves its local problem to
convergence and the server averages once, the $E \to \infty$, $R = 1$
extreme of Algorithm~\ref{alg:fedavg}
\citep{lee2017,battey2018}.

\paragraph{Local-only.} The Lasso fitted at the largest site alone, with no
communication. This is the do-nothing baseline, and it is the relevant one:
a federated procedure that does not beat it is not worth deploying.

\subsection{Matched tuning rules}
\label{sub:matched}

Selection metrics are sensitive to how the penalty is chosen, and a
comparison in which one method is tuned for sparsity and its baselines for
prediction is not a comparison of aggregation rules. We therefore report
every non-federated comparator twice: once with the penalty minimising
validation MSE (the rule used inside the protocol for $\lambda_j$, labelled
without a suffix) and once with the one-standard-error rule (suffix
\textsc{-1SE}), which is the rule \textsc{FedAvg-ST} and \textsc{FedAvg-P}
use for their thresholds. The honest reading of the results is the
\textsc{-1SE} column; we give both.

\subsection{Reporting conventions}

A coefficient is called active when $|\hat\bbeta_k| > \epsilon$ with
$\epsilon = 10^{-4}$; because the aggregated iterate carries many
small non-zero entries, results for plain averaging are sensitive to
$\epsilon$ and we report that sensitivity explicitly in
Section~\ref{sec:results}. Support quality is summarised by precision,
recall, $F_1$ and the Jaccard index against the true support in simulation,
and against the pooled Lasso support in the data illustration, where the
truth is unknown. Estimation quality is $\|\hat\bbeta - \bbeta^\star\|_2$
and prediction quality is mean squared error on an independent test sample
of $2000$ observations. Cost is reported on both axes: upload in KiB and
total coordinate-descent epochs per site.
